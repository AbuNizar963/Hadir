# حاضِر · نظام الحضور والانصراف الإلكتروني

**حاضِر** هو نظام ويب حديث لإدارة حضور وانصراف الموظفين، مصمم ليكون عمليًا وآمنًا وقابلًا للتوسع. يتيح للموظف تسجيل الحضور والانصراف من الهاتف، مع تطبيق طبقات تحقق متعددة، ويوفر للإدارة لوحة مركزية لمتابعة الموظفين والطلبات والسجلات.

## أبرز المزايا

- تسجيل دخول الموظفين والإدارة مع حماية كلمات المرور باستخدام Hash آمن.
- ربط حساب الموظف بجهاز معتمد ومنع الاستخدام غير المصرح به من أجهزة أخرى.
- التحقق من موقع الموظف عبر GPS والمسافة من موقع العمل.
- التحقق من رمز QR الخاص بموقع العمل.
- منع تسجيل الحضور المكرر أو تسجيل الانصراف دون حضور مفتوح.
- احتساب التأخر وساعات العمل وفق إعدادات الدوام.
- سجل تدقيق للعمليات والنتائج ومحاولات الرفض.
- لوحة إدارة لمتابعة الحضور المباشر، المتأخرين، الغياب، المخالفات والعمليات الإدارية.
- إدارة الموظفين: إضافة، تعديل، إيقاف، حذف وإلغاء ربط الجهاز.
- دعم الموظف عند الانتقال إلى هاتف جديد من خلال **طلب إعادة ربط الجهاز** وإرساله إلى الإدارة للمراجعة والموافقة.
- وصول طلبات إعادة ربط الأجهزة إلى **المالك والمدير والمشرفين المخولين** حسب صلاحيات النظام.
- إشعارات مركزية للموظفين والإدارة، مع حالات القراءة والأولوية ونوع الإشعار.
- إدارة طلبات الإجازات والمهام والمخالفات ومراجعات الأداء وكشوف الرواتب.
- تقارير يومية وشهرية مع إمكانية التصدير إلى CSV.
- إعدادات مركزية لأوقات الدوام، مهلة التأخر، الانصراف المبكر، الدوام الإداري والتناوبي وأيام التناوب.
- أدوات تحكم جماعية للمالك لتطبيق الإعدادات على الموظفين دفعة واحدة.
- دعم صور الملفات الشخصية وتخزينها في Cloudflare R2.

## بيانات الدخول التجريبية

> بيانات الاختبار مخصصة للبيئة التجريبية فقط، ويجب تغيير بيانات الإدارة قبل الاستخدام الفعلي.

- **الموظفون:** `1001` / `1002` / `1003` — كلمة المرور: `1234`
- **المدير:** كلمة المرور الافتراضية: `admin1234`

يتم إنشاء البيانات التجريبية تلقائيًا عند الحاجة. تتوفر عملية إعادة تعيين بيانات الاختبار من إعدادات الإدارة.

## بنية المشروع

```text
src/
  pages/         صفحات التطبيق للموظف والإدارة
  components/    مكونات واجهة المستخدم والمكونات المشتركة
  lib/           التخزين، المصادقة، الحضور، الموقع، الإشعارات، والتكامل مع Backend
  types/         تعريفات TypeScript ونماذج البيانات
```

## التشغيل محليًا

```bash
npm install
npm run dev
```

يمكن فتح النظام من الهاتف عبر نفس الشبكة باستخدام إعداد الاستضافة المناسب مثل `--host` عند الحاجة.

> **ملاحظة:** صلاحية GPS في المتصفح تتطلب `HTTPS` أو `localhost`.

## بناء المشروع

```bash
npm run build
```

ينتج البناء النسخة الجاهزة للنشر داخل مجلد `dist/` وفق إعدادات المشروع.

## النشر والاستضافة

يمكن نشر واجهة التطبيق باستخدام خدمات الاستضافة الحديثة مثل Vercel أو Netlify أو Cloudflare Pages، مع تفعيل HTTPS وربط النطاق المخصص عند الحاجة.

عند استخدام Backend، يجب التأكد من أن عنوان API المستخدم في الإنتاج متاح عبر HTTPS ومهيأ بشكل صحيح مع واجهة التطبيق.

## Cloudflare D1 Backend

يعتمد النظام حاليًا على **Cloudflare D1** لحفظ بيانات التشغيل بصورة دائمة، مع دعم **Cloudflare R2** لتخزين صور الملفات الشخصية عند تفعيل الحاوية.

يتضمن Backend جداول وواجهات لإدارة:

- الموظفين والحضور والانصراف.
- الإشعارات.
- سجل التدقيق.
- المخالفات وطلبات الإجازات.
- المهام ومراجعات الأداء والرواتب.
- الأحداث غير الطبيعية والتحليلات الذكية.
- اشتراكات الإشعارات.
- أحداث الهروب والعودة.
- طلبات إعادة ربط أجهزة الموظفين.

### طلب إعادة ربط جهاز الموظف

عند محاولة الموظف استخدام هاتف جديد بينما يوجد جهاز مرتبط بحسابه، يستطيع إرسال **طلب إعادة ربط الجهاز** بدلًا من تجاوز الربط.

يمر الطلب بالمسار التالي:

1. يتحقق النظام من بيانات الموظف ورمز الدخول.
2. يتم إنشاء طلب إعادة ربط بحالة `pending`.
3. يُرسل إشعار إلى الحسابات الإدارية المخولة.
4. يظهر الطلب في قسم طلبات إعادة ربط الأجهزة لدى الإدارة.
5. يمكن للإداري المخول **الموافقة** أو **الرفض**.
6. عند الموافقة، يتم فك ارتباط الجهاز القديم مع إبقاء حساب الموظف وبياناته محفوظة.
7. يتلقى الموظف إشعارًا بالنتيجة ويمكنه متابعة تسجيل الدخول من الجهاز الجديد.

## الصلاحيات

يستخدم النظام مستويات صلاحيات منفصلة لضمان عدم تنفيذ العمليات الحساسة من المستخدمين غير المخولين:

| الدور | نطاق الصلاحيات |
|---|---|
| **المالك** | تحكم كامل وإعدادات النظام والعمليات الجماعية الحساسة |
| **المدير** | إدارة الموظفين والمتابعة والطلبات والعمليات الإدارية المصرح بها |
| **المشرف** | المتابعة والعمليات التي تسمح بها صلاحيات الإشراف |
| **الموظف** | تسجيل الحضور والانصراف وإدارة بياناته والطلبات المتاحة له |

## الإشعارات

يوفر النظام مركز إشعارات موحدًا للموظفين والإدارة، ويستخدم الإشعارات للأحداث المهمة مثل:

- طلبات إعادة ربط الأجهزة.
- الموافقة أو الرفض على الطلبات.
- المخالفات والتنبيهات.
- تسجيل حالات الهروب والعودة.
- التحديثات الإدارية المهمة.

يتم حفظ الإشعارات في Backend مع إمكانية تحديد حالة القراءة ونوع الإشعار ومستوى أهميته.

## الأمان

تم تصميم النظام ليعتمد على التحقق من الهوية والصلاحيات في Backend، وليس على واجهة المستخدم وحدها. تشمل طبقة الحماية:

- Hash لكلمات المرور باستخدام PBKDF2 في Backend.
- التحقق من الدور والصلاحيات قبل تنفيذ العمليات الحساسة.
- جلسات ومصادقة مركزية عند تفعيل Backend.
- سجل تدقيق للعمليات الإدارية والحساسة.
- عدم السماح للموظف بفك ربط جهازه مباشرة؛ تتم العملية عبر طلب ومراجعة إدارية.
- التحقق من حالة الموظف والجهاز قبل العمليات المتعلقة بالحضور أو إعادة الربط.

> يجب استخدام HTTPS في بيئة الإنتاج، وعدم استخدام بيانات الدخول التجريبية أو أسرار التطوير في بيئة حقيقية.

## حدود الإصدار التجريبي

بعض أجزاء الواجهة أو بيانات الاختبار قد تكون مخصصة للتطوير والعرض. قبل الاستخدام التجاري الكامل يجب مراجعة إعدادات المصادقة، الجلسات، Rate Limiting، النسخ الاحتياطي، سياسات الوصول إلى قاعدة البيانات، ومفاتيح الخدمات السرية.

## خطة التطوير المستقبلية

- تحسين إدارة الجلسات والرموز الأمنية في الإنتاج.
- إضافة Rate Limiting وحماية إضافية ضد محاولات الدخول المتكررة.
- تحسين مراقبة الأجهزة وربطها بطريقة أكثر مقاومة للتحايل.
- تطوير تقارير الحضور والرواتب بصورة أوسع.
- دعم Push Notifications بصورة كاملة عند الحاجة.
- إضافة اختبارات آلية للواجهات وواجهات Backend.
- تحسين المراقبة والتنبيهات الخاصة بالخدمات وقاعدة البيانات.
- إمكانية دعم Capacitor للتحقق من إشارات Wi‑Fi أو Bluetooth داخل موقع العمل عند الحاجة.
