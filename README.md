# حاضِر · نظام الحضور والانصراف الإلكتروني (V1.1 MVP)

نظام ويب Web App لتسجيل حضور وانصراف الموظفين من الهاتف عبر رابط، مع طبقات تحقق:
ربط الحساب بالجهاز + التحقق من الموقع (GPS) + رمز QR ثابت + سجل تدقيق دائم.

## بيانات دخول تجريبية

- **موظفون**: `1001` / `1002` / `1003` — كلمة المرور: `1234`
- **مدير**: كلمة المرور: `admin1234`

> يتم إنشاء بيانات تجريبية تلقائيًا عند أول تشغيل. لإعادة التعيين: صفحة إعدادات المدير → "إعادة تعيين البيانات التجريبية".

## بنية المشروع (Frontend)

```
src/
  pages/         صفحات التطبيق (موظف/مدير)
  components/    مكونات مشتركة
  lib/           منطق: التخزين، المصادقة، الحضور، الموقع، التدقيق
  types/         تعريفات TypeScript
```

## تشغيل النظام محليًا

```bash
npm install
npm run dev
```

ثم افتح الرابط في الهاتف عبر نفس الشبكة (استخدم `--host` عند الحاجة).
> ملاحظة مهمة: GPS في المتصفحات يتطلب **HTTPS** أو `localhost`.

## نشر النسخة الحالية على الإنترنت

يمكن نشر هذا الجزء Frontend مباشرة عبر:
- **Vercel** / **Netlify** / **Cloudflare Pages** (رفع `dist/` بعد `npm run build`).
- استخدم دومين باسمك، وفعّل HTTPS (تلقائي في المنصات أعلاه).

## ماذا يعمل في V1.0 (مبني على المتصفح)

- تسجيل دخول الموظف والمدير مع Hash لكلمة المرور.
- ربط الحساب بالجهاز عند أول تسجيل دخول (رفض المحاولات من أجهزة أخرى).
- الحصول على GPS والتحقق من المسافة من مقر العمل.
- مسح رمز QR الثابت (محاكاة قابلة للاستبدال بكاميرا حقيقية).
- منع تسجيل حضور مكرر، ومنع انصراف قبل حضور.
- حساب التأخر وساعات العمل.
- سجل تدقيق كامل لكل عملية (نجاح/رفض).
- لوحة مدير: KPIs، حضور مباشر، متأخرون، غياب، محاولات مرفوضة.
- إدارة الموظفين: إضافة/تعديل/إيقاف/إلغاء ربط الجهاز/حذف.
- تقارير يومية وشهرية مع تصدير CSV.
- إعدادات: موقع المقر، النطاق، رمز QR، أوقات الدوام، كلمة مرور المدير.

## الحدود (يجب معالجتها في مرحلة الإنتاج)

هذه النسخة تنفّذ منطق التحقق على المتصفح (localStorage) لأغراض العرض والاختبار.
**للإنتاج** يجب:

1. نقل المنطق (تحقق الجهاز، فحص GPS، التحقق من QR، سجل التدقيق) إلى **Backend** حقيقي.
2. استخدام **PostgreSQL** لتخزين الموظفين والعمليات والسجلات.
3. تخزين كلمات المرور بـ **bcrypt/argon2** على الخادم.
4. **HTTPS إجباري** + JWT/Session آمنة + Rate limiting.
5. الحصول على **IP** الفعلي من رأس الطلب على الخادم.
6. توثيق الجهاز بـ token طويل الأمد يُصدره الخادم عند أول ربط (Cookie آمنة + fingerprint).
7. سجل التدقيق: append-only في قاعدة البيانات (لا SELECT/UPDATE للمستخدم العادي).
8. اختيارياً: التحقق من SSID/BSSID لشبكة Wi-Fi الخاصة بالمقر عبر Native Wrapper (Capacitor)، أو Bluetooth Beacon، لتقوية إثبات وجود الجهاز داخل المقر.

## المسار المقترح للترقية إلى Backend

- استخدام **OnSpace Cloud** (متوافق مع Supabase): PostgreSQL + Auth + Edge Functions،
  حيث تنتقل ملفات `src/lib/attendance.ts` و `src/lib/auth.ts` إلى Edge Functions،
  ويحل REST محل localStorage.
- الاحتفاظ بنفس نموذج البيانات المُعرَّف في `src/types/index.ts`.

## الملكية

- الدومين والاستضافة وقاعدة البيانات تحت اسمك.
- حساب المدير الافتراضي يجب تغيير كلمة مروره من صفحة الإعدادات فور التشغيل.
